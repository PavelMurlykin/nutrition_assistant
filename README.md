# Nutrition Assistant

Автономный дневник питания и здоровья для Android 8.0+ на Kotlin и Jetpack Compose. Интерфейс на русском языке. Все данные находятся в Room на устройстве; сервер, учетная запись и интернет не используются. Единственное разрешение итогового приложения — POST_NOTIFICATIONS.

## Возможности

- Дневник по выбранной дате: завтрак, обед, ужин, несколько перекусов, приемы нескольких лекарств, стул, сон, самочувствие и вода.
- Единый стиль экранов и всех окон приложения: зелёная палитра, общая типографика Sans Serif, скруглённые карточки и поля, светлая и тёмная темы по Android. Длинные формы прокручиваются, черновики переживают пересоздание экрана; отмена изменений и удаление требуют подтверждения.
- Нижние вкладки: «Расписание» (время напоминаний), «Календарь» (календарь и дневник), «Меню» (справочники блюд, продуктов и лекарств), «Данные» (резервные копии JSON).
- Календарь с перелистыванием месяцев стрелками и свайпом, отметками еды, лекарств и туалета, выбором дня и кнопкой «Сегодня». При прокрутке дневника календарь сворачивается; кнопка «+» добавляет запись на выбранную дату.
- Блюда делятся на домашние и ресторанные. При добавлении и редактировании состав выбирается чекбоксами из справочника продуктов; поиск по части названия фильтрует список при вводе.
- Встроены 100 базовых продуктов, 15 категорий, варианты с марками, вложенный состав, источники и комментарии. Есть избранное, недавние позиции, архив и повтор приёма с проверкой состава.
- Блюда, продукты и лекарства ищутся по частичному совпадению. Недостающий продукт можно создать из редактора блюда и сразу включить в состав.
- Допускается несколько завтраков, обедов и ужинов за день. Прием пищи объединяет несколько блюд и отдельных продуктов. Прием лекарств объединяет несколько препаратов с отдельными дозировками.
- Для типов стула 1–2 и 6–7 анализируется предыдущий календарный день: блюда, тип еды, ингредиенты и частота совпадений в истории.
- Четыре независимых ежедневных напоминания с выбором времени и выключателем: завтрак, обед, ужин, туалет.
- Экспорт полного дневника, справочников, архива и настроек в JSON 3; импорт JSON 1–3. Импорт с проверкой, предпросмотром, явным сопоставлением справочников, сохранением локальных конфликтующих записей и откатом при ошибке. Повторный импорт не создаёт дублей.
- Миграции базы 1 → 2 → 3 → 4 → 5 → 6 сохраняют старые записи. Категория «Магазинная» удалена: её позиции перенесены в «Продукты», а состав блюд связан с продуктами. Схема 4 добавляет постоянные UUID для переноса. Схема 5 поддерживает вложенный состав, варианты товаров, количества, фактическое время и полноту дня; формы каталога, порций и обновления состава доступны. Схема 6 сохраняет избранное. Ввод времени и состояния — этап 6. Изменение справочника не переписывает состав записанных событий.

## Сборка и проверки

Нужны JDK 17 или 21, Android SDK Platform 37 и SDK Build Tools 36.0.0, доступный SDK через ANDROID_HOME или local.properties. Gradle Wrapper 9.6.0 включен в репозиторий. Используются Android Gradle Plugin 9.5.1, Kotlin 2.4.21 через встроенную поддержку AGP, KSP 2.3.14 и Room 2.8.5 с поддержкой KSP2. Первая сборка загружает зависимости.

В Android Studio выберите JDK 21 в **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK**. Если выбрано `GRADLE_LOCAL_JAVA_HOME`, путь берется из `java.home` в локальном `.gradle/config.properties`. Для сборки из терминала отдельно задайте `JAVA_HOME` на JDK 17 или 21. Проверка сборки выполняется с JDK 21. Подробности приведены в руководствах.

```powershell
./gradlew.bat :app:assembleDebug
./gradlew.bat :app:testDebugUnitTest :app:lintDebug
./gradlew.bat :app:connectedDebugAndroidTest
```

Последняя команда требует запущенного Android-эмулятора или подключенного тестового устройства. Debug APK: app/build/outputs/apk/debug/app-debug.apk. На macOS/Linux используйте ./gradlew.

Тесты проверяют аналитику, поиск, составные события, сохранность истории, миграции, создание блюда через интерфейс, полный цикл восстановления JSON, повторный импорт, конфликты, устаревший предпросмотр и транзакционный откат.

## Ограничения платформы и данных

Напоминания неточные: Android может задерживать их. После перезагрузки или принудительной остановки приложение нужно открыть снова. Автовосстановление при загрузке потребовало бы дополнительного разрешения RECEIVE_BOOT_COMPLETED, которого здесь нет. Синхронизация и автоматическая облачная копия не реализованы. Перед удалением приложения сохраните JSON во вкладке «Данные»: удаление удаляет локальную базу. JSON не зашифрован; лимит — 16 МиБ и 100 000 объектов и компонентов, поддерживается один локальный профиль. Импорт объединяет данные; полной замены базы нет.

Аналитика показывает наблюдаемые совпадения, а не устанавливает причину заболевания. Пропущенные записи не считаются здоровыми днями. Лекарства сохраняются в дневнике, но их влияние на стул алгоритм не рассчитывает.
