# Nutrition Assistant

Android-приложение на Kotlin + Jetpack Compose для переноса функциональности `poop_stats_bot` в локальное мобильное приложение.

## Что уже есть

- два стартовых экрана:
  - `Расписание` для настройки временных слотов напоминаний;
  - `Дневная статистика` с выбором даты через календарь и CRUD по основным категориям;
- локальная база `Room`, повторяющая текущую PostgreSQL-модель бота;
- планирование локальных уведомлений через `AlarmManager`;
- архитектурное разделение на `data / ui / notification`, чтобы позже без сильной переделки добавить API и синхронизацию.

## Совместимость со схемой бота

В Android-проект уже перенесены таблицы:

- `users`
- `meals`
- `medicines`
- `stools`
- `feelings`
- `water`
- `sleeps`
- `notifications_log`

Названия таблиц и полей сохранены максимально близко к схеме из `poop_stats_bot`, чтобы в следующем этапе было проще:

- импортировать существующие PostgreSQL-данные пользователей;
- сделать двустороннюю синхронизацию через удаленный сервер;
- переиспользовать текущую бизнес-логику расписания и дневных записей.

## Текущая структура

```text
app/src/main/java/com/pavel/nutritionassistant/
  data/
    local/        Room entities, DAO, database
    model/        enums и агрегированные модели экрана
    repository/   единая точка работы с локальными данными
  notification/   ресиверы и планирование уведомлений
  ui/
    schedule/     экран расписания
    daily/        экран дневной статистики
    components/   общие карточки и пикеры
    theme/        тема и палитра
```

## Важные допущения текущего этапа

- локальный пользователь пока один: `user_id = 1`;
- напоминания работают только локально на устройстве;
- `sleep_quality` рассчитывается как `wakeup_time + 30 минут`, как и в боте;
- `Room` используется как стартовая локальная реплика схемы, а не как окончательный источник истины.

## Что логично сделать следующим шагом

1. Добавить импорт из PostgreSQL/JSON-дампа старого бота.
2. Вынести доменные модели и use-case слой для синхронизации.
3. Подключить серверное API и стратегию conflict resolution.
4. Добавить тесты для репозитория и миграций.
