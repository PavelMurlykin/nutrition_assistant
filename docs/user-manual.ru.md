# Руководство пользователя Nutrition Assistant

## Установка и запуск

Иконка приложения — зелёный «Календарь питания» с тарелкой, вилкой и ложкой. Она адаптируется к круглой и другим формам значков Android. На Android 13+ предусмотрен монохромный вариант для лаунчеров с включёнными тематическими значками.

Приложение работает на Android 8.0 и новее. Откройте проект в Android Studio с JDK 17 или 21, Android SDK Platform 37 и SDK Build Tools 36.0.0 либо соберите APK командой:

```powershell
./gradlew.bat :app:assembleDebug
```

Gradle Wrapper 9.6.0 входит в проект. Сборка использует Android Gradle Plugin 9.5.1, Kotlin 2.4.21 через встроенную поддержку AGP, KSP 2.3.14 и Room 2.8.5 с поддержкой KSP2. Для сборки задайте путь SDK через ANDROID_HOME или local.properties; при первой сборке нужен интернет для зависимостей. APK находится в app/build/outputs/apk/debug/app-debug.apk. Для установки откройте APK на тестовом устройстве и разрешите установку из выбранного источника в Android. На macOS/Linux команда — ./gradlew :app:assembleDebug.

### Выбор Java для Gradle

В Android Studio откройте **Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK** и выберите установленный JDK 21 (для текущего проекта также подходит JDK 17). Если выбран `GRADLE_LOCAL_JAVA_HOME`, используется свойство `java.home` из локального файла `.gradle/config.properties`. Этот файл не включается в Git: путь зависит от компьютера. После изменения выполните **Sync Project with Gradle Files**.

Проверка сборки выполняется с JDK 21. Java для запуска самой Android Studio настраивается отдельно. Для терминала задайте `JAVA_HOME`; он не читает `.gradle/config.properties` автоматически. Сообщение `JAVA_HOME is not set and no 'java' command could be found in your PATH` означает, что Java не настроена для терминала. Пример для установленного на этом компьютере JDK:

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\openjdk\jdk-21.0.8'
./gradlew.bat --version
./gradlew.bat :app:assembleDebug
```

На другом компьютере укажите свой путь. Команда `--version` должна показывать совместимую JVM. [Настройка Gradle JDK в Android Studio](https://developer.android.com/build/jdks).

После запуска открывается «Календарь» с дневником текущей даты. Нижняя панель: «Расписание» — настройка времени напоминаний, «Календарь» — записи и статистика по дням, «Меню» — справочники блюд, продуктов и лекарств, «Данные» — резервные копии JSON. Светлая или тёмная тема выбирается автоматически по настройке Android; палитра, карточки и календарь основаны на sports_activity_assistant. Интернет, регистрация и сервер для работы не нужны. Данные находятся в локальной базе Room одного пользователя. Автоматическое облачное резервное копирование и синхронизация отсутствуют. Перед удалением приложения сохраните JSON во вкладке «Данные»: удаление приложения удаляет локальную базу.

## Единый интерфейс и формы

В версии 0.6.0 экраны, редакторы, выбор даты/времени, подтверждения, ошибки и проверка импорта используют общие шрифты, поля, отступы и кнопки. Светлая и тёмная темы следуют настройке Android. Размер текста следует системному; длинные формы и списки прокручиваются, кнопки переносятся при нехватке ширины. В низком окне с клавиатурой может потребоваться прокрутить всю форму до действий.

Открытый редактор, введённый текст, выбранные позиции еды и дозировки сохраняются при пересоздании экрана, например повороте устройства. Они становятся записями дневника только после сохранения. Если значения записи изменены, «Отмена», возврат или нажатие за пределами окна предлагают «Отбросить» изменения; отмена этого подтверждения возвращает к черновику. Новые продукты и другие записи справочника, уже сохранённые из вложенного редактора, остаются в справочнике при отмене родительской формы.

Удаление записи дневника и «Убрать из справочника» сначала открывают подтверждение. Ошибка действия с дневником или справочником показывается отдельным окном «Не удалось выполнить действие»; «Понятно» возвращает к введённым данным. Недопустимое значение поля подсвечивается, сохранение блокируется до исправления. Во время сохранения повторное действие и закрытие редактора блокируются.

Дата вводится восемью цифрами, например `17112026` → `17.11.2026`; время — четырьмя цифрами с ведущим нулём, например `0935` → `09:35`. Разделители добавляются автоматически. «Выбрать» применяет значение, несуществующая дата или время вне 00:00–23:59 не принимаются. Системный выбор файлов и разрешения Android имеют оформление самой системы.

## Календарь и дневник

Календарь показывает шесть недель с понедельника, включая соседние месяцы. Стрелки и горизонтальный свайп перелистывают месяцы; при переходе выбирается первое число нового месяца, как в sports_activity_assistant. Нажмите день, чтобы открыть его записи: день из соседнего месяца также переключит месяц. «Сегодня» возвращает текущую дату, «Выбрать дату» под календарём открывает окно ввода даты в стиле приложения. Сегодняшний день обведён, выбранный день подсвечен; выбор дня и открытый месяц сохраняются при пересоздании экрана и переключении вкладок.

Значки еды, лекарств и туалета отмечают дни с сохранёнными событиями. В заголовке дневника показано количество приёмов пищи, приёмов лекарств и посещений туалета за выбранный день. Несколько блюд в одном приёме пищи или препаратов в одном приёме лекарств считаются одним событием. Изменения и удаления автоматически обновляют календарь; пустой день не считается днём без симптомов.

При вертикальной прокрутке дневника календарь уменьшается, а при возврате вверх разворачивается; его также можно прокручивать жестом по самому календарю. На низком экране и при крупном системном шрифте календарь прокручивается вместе с дневником. «+» открывает выбор записи: завтрак, обед, ужин, перекус, приём лекарств или туалет. Выбор типа всегда создаёт новое событие; для изменения используйте «Изменить» у нужной записи. Другие разделы доступны ниже в дневнике. В каждом разделе можно добавлять, изменять и удалять записи. Просмотр дня сам по себе не создаёт записи.

За день можно записать несколько завтраков, обедов, ужинов, перекусов и приёмов лекарств. Каждый приём пищи может содержать одно блюдо, один продукт или их сочетание. Стул и самочувствие также допускают несколько записей. Для сна и количества воды хранится одна запись за день.

### Питание

1. Нажмите «Добавить» в нужном приёме пищи либо «Изменить» у существующей записи.
2. Выберите «Блюда» и тип еды «Домашняя» или «Ресторанная», либо «Продукты» для отдельного продукта.
3. Введите часть названия. Список совпадений меняется при вводе; регистр, лишние пробелы и различие е/ё не мешают поиску.
4. Нажмите блюдо или продукт, чтобы включить его в событие. Можно выбрать несколько позиций и переключаться между разделами и типами еды. «Убрать из события» снимает выбор.
5. Для новой позиции или варианта нажмите «Добавить … в справочник и выбрать». Для блюда укажите название, тип и отметьте продукты чекбоксами; хотя бы один продукт обязателен. Для продукта выберите категорию (по умолчанию «Прочее»); при необходимости укажите конкретный товар, марку и состав. Новая запись сразу включается в событие.
6. Нажмите «Сохранить событие».

Поиск событий показывает до 40 совпадений; при необходимости уточните название. Свободный текст поиска сам по себе не сохраняется как блюдо или продукт. Пустое событие сохранить нельзя. Созданная запись справочника остаётся в нём даже при последующей отмене события.

### Лекарства

Нажмите «Добавить прием» и найдите лекарство по части названия. Если его нет, создайте запись из этого же окна: она сразу будет выбрана. Можно выбрать несколько лекарств и указать отдельную дозировку или количество для каждого. Дозировка необязательна и вводится вручную. Справочник лекарств изначально пуст; приложение не рекомендует препараты или дозы.

### Стул

В разделе «Туалет» выберите тип 1–7 по Бристольской шкале. Типы 1–2 отмечаются как признаки запора, 6–7 — как жидкий стул/понос, 3–4 — как оформленный, 5 — как мягкий стул. Это категории дневника, а не диагноз. Старые записи со значением 0 остаются «не оценены»; новые записи с 0 не создаются.

После сохранения типа 1–2 или 6–7 карточка «Аналитика стула» автоматически обновляется. Она показывает еду за предыдущий календарный день относительно даты события: например, для записи 18 октября анализируется 17 октября, включая перекусы. Это не скользящее окно в 24 часа.

Алгоритм сравнивает блюда, продукты, типы еды и известные ингредиенты. Отдельно записанный продукт также учитывается как ингредиент при сравнении с составом блюд. Для каждого фактора показаны дни с выбранным нарушением / все наблюдаемые дни после употребления и без употребления. Несколько записей стула или повторов ингредиента в один день не умножают число дней. Каждый тип нарушения анализируется отдельно. Учитывается история только до выбранной даты включительно.

Сравнение использует лишь дни с оцененным стулом и с записями о еде накануне. Отсутствие записи не считается нормальным стулом или отсутствием симптома. «Повторяющаяся связь» означает минимум два дня с этим нарушением после фактора, минимум два наблюдаемых дня без фактора и более высокую частоту нарушения с фактором. Показаны до 12 факторов, сначала повторяющиеся связи, затем по разнице частот. При нехватке данных это указано явно.

Совпадение не доказывает причину. Под «без фактора» понимаются дни, когда он не записан накануне; результат зависит от полноты дневника. Алгоритм не рассчитывает влияние лекарств, инфекций, воды, сна или самочувствия. Он не дает диагнозов и рекомендаций по лечению или исключению продуктов.

### Сон, самочувствие и вода

Сон вносится вручную: подъём в выбранный день и свободное описание качества. В новой записи отбой раньше времени подъёма относится к тому же дню, отбой позже или в то же время — к предыдущему дню. Хранятся даты конкретной ночи; интервал в постели не считается фактической длительностью сна. У старых записей неизвестные даты ночи сохраняются. Значения 23:00 и 07:00 в новом окне — только начальные значения формы; запись создается после сохранения. Самочувствие описывается текстом. Для воды доступны кнопки −1, +1 и точный ввод количества стаканов; отрицательные значения не допускаются.

## Меню: справочники и состав

В версии 0.8.0 встроены 100 базовых продуктов во всех 15 категориях, включая гречку, рис, яйца, мясо и виды фарша. У общих названий хлеба, пельменей и фарша состав остаётся неизвестным. Предустановленные блюда новой установки помечены комментарием «Шаблон рецепта»: проверьте их под свой рецепт. Приложение не угадывает лактозу, чеснок или отсутствие добавок по названию.

В «Меню» выберите «Блюда», «Продукты» или «Лекарства». Для блюд доступны домашние и ресторанные; для продуктов — «Категория». Поиск учитывает имя, марку и уточнение; «Искать в составе» ищет также вложенные ингредиенты, например чеснок в котлете через фарш. «Все», «Избранное», «Недавние» ускоряют выбор. Недавние — до 30 позиций из записанной истории, по локальной дате/времени; архивные позиции скрыты из обычного выбора.

«В избранное» сохраняет отметку. «Архив» показывает убранные записи; «Вернуть в справочник» восстанавливает ту же идентичность со всеми сведениями. Архивирование требует подтверждения и сохраняет историю и связи рецептов. Создание новой позиции даёт отдельный UUID, даже при одинаковом названии; для прежней записи используйте «Изменить» или восстановление архива.

Для продукта задайте название и категорию. «Базовый продукт» подходит общей позиции; «Конкретный товар» раскрывает марку и уточнение варианта. Так два хлеба с разным составом хранятся отдельно и различаются в списках и истории. «Уточнить состав продукта» позволяет выбрать продукты-компоненты, включая составные. Для блюда укажите домашний/ресторанный тип и хотя бы один продукт.

«Поиск продуктов» фильтрует компоненты при вводе, сохраняя отмеченные галочки. Можно создать недостающий продукт в этом же редакторе, уточнить состав и сразу включить в рецепт; он останется в справочнике и при отмене блюда. «Количества компонентов» открывает необязательные количества и единицы. Циклы и чрезмерно большой состав отклоняются без частичного сохранения.

«Сведения о составе и комментарий» раскрывает статусы «Состав неизвестен», «Частичный состав», «Подтверждён по источнику», источник, дату проверки и необязательный комментарий. Подтверждение требует источника и даты. Изменение состава или количества в подтверждённой форме снимает статус подтверждения до новой проверки. Источник хранится как введённый текст; приложение не проверяет упаковку за пользователя. Названия, марки, уточнения и комментарии ограничены 1000 символами.

«Состав и источники» показывает пути вроде «котлета → покупной фарш → чеснок», версии, известные количества и источники каждого узла. Неизвестный или частичный состав не подтверждает отсутствие ингредиента. На экране показываются первые 200 узлов; полный снимок сохраняется в резервной копии.

Встроенные продукты имеют стабильные ключи. Обновление добавляет новые позиции и сохраняет пользовательские исправления, избранное и архив. При первом обновлении прежняя единственная базовая запись с тем же нормализованным именем связывается с ключом; отсутствующая категория заполняется только у записи версии 1. Если прежних совпадений несколько, в «Меню» появится «Уточнить совпадения встроенного каталога»: выберите существующую позицию или «Создать встроенный отдельно». Неоднозначные записи не сливаются автоматически.

### Порции, история и повтор

В форме приёма доступны те же фильтры категорий, избранное, недавние позиции и поиск состава. «Состав» у результата показывает текущие сведения; «Состав позиции» у выбранной или записанной еды — её собственный снимок. Блюдо, один продукт (например пельмени) и сочетание «котлета + пюре + огурец» сохраняются одним событием.

«Порция и комментарий» раскрывает количество и комментарий позиции; «Комментарий приёма» — общий комментарий. Количество — положительное число, единица выбирается вместе с ним: г, мл или шт. Пусто означает неизвестность; ноль не используется как замена пропуска, автоматического пересчёта единиц нет. Для лекарства сохраняется отдельная свободная дозировка.

Обычная правка каталога или комментария события сохраняет прежний состав еды. «Обновить состав» в редакторе записанного события показывает старое и текущее дерево. «Использовать текущий состав» меняет только выбранную позицию после «Сохранить событие»; порция и комментарий сохраняются. Если состав изменился после выбора, сохранение останавливается и просит проверить позицию заново.

«+» → «Повторить недавний приём» предлагает последние 10 приёмов. Проверьте состав, порции и выбранную дату, уберите лишние позиции или явно обновите их состав. По умолчанию сохраняются исторический состав и порции; создаются новые UUID события и позиций, исходный приём остаётся прежним. Старое фактическое время не копируется. Архивные позиции обозначены отдельно и требуют вашей проверки.

Формы фактического времени, шкал состояния и полноты дня относятся к этапу 6. Уже сохранённые время и дополнительные сведения сохраняются при обычном редактировании. Подтверждения полноты по умолчанию отсутствуют и ещё не используются текущей аналитикой. Изменения питания снимают подтверждение питания, стула или самочувствия — симптомов.

Экспорт создаёт JSON 3; импорт читает JSON 1–3. Снимки состава ограничены 16 уровнями и 10 000 развёрнутыми узлами на приём. Старые плоские ингредиенты и неизвестные значения не дополняются придуманными источниками или количеством.

## Напоминания и разрешение

Во вкладке «Расписание» есть четыре независимых ежедневных напоминания: завтрак (08:00), обед (13:00), ужин (19:00), туалет (09:00). По умолчанию они включены, но доставка требует разрешения уведомлений. Выключатель отключает нужный вид; «Изменить время» открывает общее окно ввода времени ЧЧ:ММ. Настройки сохраняются локально после «Выбрать».

Единственное разрешение приложения — POST_NOTIFICATIONS. На Android 13+ запрос появляется по кнопке «Разрешить уведомления». Если Android больше не показывает запрос, откройте «Открыть настройки Android» и включите уведомления там. На Android 8–12 этой кнопкой открываются системные настройки. Дневник доступен и при отказе в уведомлениях. Канал уведомлений также можно отключить в настройках Android.

Сон, самочувствие, перекусы, лекарства и вода вводятся вручную, без напоминаний. Нажатие уведомления открывает дневник. Каждый вид уведомления отправляется не более одного раза за локальный календарный день.

Android может задерживать неточные напоминания для экономии батареи. После перезагрузки или принудительной остановки откройте приложение для их восстановления. Автоматическое восстановление при загрузке и точные будильники потребовали бы дополнительных разрешений, поэтому они не используются. При изменении времени или часового пояса расписание пересчитывается.

## Данные: резервная копия JSON

Откройте нижнюю вкладку «Данные». Резервная копия содержит весь дневник, справочники, архивные позиции, исторический состав еды, дозировки, текст самочувствия и качества сна и настройки напоминаний. Текущий фильтр даты не ограничивает копию. Файл не зашифрован и содержит сведения о здоровье; место хранения и передачу выбираете вы.

### Экспорт

1. Нажмите «Экспорт резервной копии» и дождитесь подготовки снимка.
2. В системном окне выберите место и сохраните файл `nutrition-backup-YYYYMMDD-HHmmss.json`.
3. Дождитесь сообщения о сохранении. Новые записи после подготовки снимка попадут в следующую копию.

Дополнительное разрешение на накопитель не нужно. Копия вне локальной базы может использоваться для переноса на другое устройство. Сохраняйте новую проверенную копию перед удалением приложения.

### Импорт

1. Нажмите «Импорт из JSON» и выберите резервную копию Nutrition Assistant JSON 1, 2 или 3 в UTF-8, до 16 МиБ и 100 000 объектов и компонентов. Копии других приложений не подходят.
2. В «Проверке импорта» проверьте количества объектов, добавляемые записи, сопоставления и конфликты. История объединяется с текущим личным дневником; база не очищается.
3. При одноимённых позициях с разными UUID отдельно подтвердите сопоставление с локальным справочником. По умолчанию текущие сведения, состав, избранное и архив сохраняются. Флажок «Восстановить состав и архив справочника из файла» заменяет текущие сведения сопоставленных продуктов, блюд и лекарств данными копии; исторические снимки еды и лекарств не переписываются. Для полного восстановления на новой установке включите этот флажок. Совпадение для переноса учитывает также базовый продукт/вариант, марку и уточнение. Если сочетание не уникально хотя бы в одном справочнике, позиции сохраняются отдельно без слияния по названию.
4. При различающихся данных подтвердите сохранение локальных записей. Конфликтующий приём сохраняется целиком вместе с его позициями; файл не перезаписывает его. Для воды, сна и подтверждений полноты дня на одну дату также сохраняется локальная запись; импорт новых наблюдений снимает соответствующее прежнее подтверждение. В длинном списке видны первые 100 подробностей каждого вида и общее число.
5. По желанию включите «Восстановить настройки напоминаний из файла». По умолчанию настройки остаются текущими. Для полного восстановления на новом устройстве включите этот флажок.
6. Нажмите «Применить импорт» и дождитесь результата. «Отмена» закрывает предпросмотр без изменения дневника.

Совпадающие UUID и подтверждённые сопоставления узнаются при повторном импорте — дубли не создаются. Операция проверяется и применяется целиком; повреждение, неизвестные поля/версия или ошибка записи не приводят к частичному переносу. Если дневник, каталог или настройки изменились после предпросмотра, выберите файл заново. Проверка и файловые операции выполняются в фоне; повторная операция на время выполнения заблокирована.

Предпросмотр и подготовленная копия сохраняются при пересоздании экрана в текущем процессе. После закрытия процесса выберите файл заново. Прерванный экспорт может оставить пустой или неполный файл: сохраните новую копию и проверьте её открытием в предпросмотре. Системное разрешение уведомлений не переносится; после восстановления проверьте «Расписание». Журнал уже отправленных уведомлений не восстанавливается. Полная замена базы, синхронизация и импорт нескольких профилей отсутствуют.

[Описание формата и синтетический пример](backup-format.md) предназначены для проверки переноса на отдельной тестовой установке.

## Обновление существующей установки

Обновляйте APK поверх прежней установки с той же подписью. Миграции Room 1 → 2 → 3 → 4 → 5 → 6 сохраняют события и настройки расписания. Схема 6 добавляет избранное, сохраняя идентичность и историю. Схема 5 добавляет вложенный состав, дополнительные сведения и снимки; старые значения остаются неизвестными, подтверждения дня не создаются. Схема 4 добавляет постоянные UUID и запоминаемые сопоставления импорта, сохраняя прежние числовые идентификаторы и снимки. В версии схемы 3 прежние позиции категории «Магазинная» переносятся в «Продукты» с сохранением идентификаторов и ссылок дневника. У записанных магазинных позиций категория заменяется пометкой «Продукт»; их названия и известный состав сохраняются. Значение категории «Магазинная» удаляется из текущих данных базы.

Прежние текстовые ингредиенты блюд становятся связанными записями продуктов; одинаковые нормализованные названия объединяются. История состава в дневнике остаётся прежней. Старое свободное описание еды из схемы 1 переносится целиком как блюдо с пометкой «Тип не указан (старая запись)», без предположений о составе. Старые лекарства сохраняют дозировки, записи сна также сохраняются.

## Проверка разработчиком

```powershell
./gradlew.bat clean :app:assembleDebug :app:assembleRelease :app:testDebugUnitTest :app:lintDebug :app:assembleDebugAndroidTest --warning-mode=all
./gradlew.bat :app:connectedDebugAndroidTest --warning-mode=all
```

Для второй команды нужен отдельный тестовый Android-эмулятор или устройство: тестовый runner может переустанавливать приложение. Тесты проверяют аналитику и поиск, составные события и дозировки, сохранность истории, миграцию, создание блюда через интерфейс, календарную сетку, подсчёт событий, навигацию и сохранение выбранной даты.
