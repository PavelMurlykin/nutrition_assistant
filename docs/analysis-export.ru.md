# Пакет дневника для внешнего анализа

Приложение 0.12.0 сохраняет выбранные данные в UTF-8. JSON имеет собственный формат nutrition-diary-analysis версии 1. Markdown представляет те же записи по датам, с расшифровкой шкал и единиц. Пакет создаётся без сети и передаётся только системному поставщику документа, которого выбрал пользователь для сохранения. Импорт поддерживает [резервные копии](backup-format.md).

## Поля JSON

| Поле | Содержимое |
| --- | --- |
| format, schema_version | nutrition-diary-analysis, 1 |
| period | Первая и последняя локальные даты включительно |
| sections, privacy | Выбранные разделы, включение комментариев и скрытие названий |
| data_rules, units | Правила времени, пропусков и неизвестного состава, единицы выбранных разделов |
| scale_dictionary, category_dictionary | Версии шкал, коды, подписи и категории выбранных разделов |
| analysis_request | Запрос пользователя к внешней модели. Пустой запрос пропускается |
| events | События с устойчивыми идентификаторами, датой, точностью времени и полями выбранных разделов |
| analytics | Необязательная сводка описательных сравнений по данным пакета |

Внутри исходной локальной даты точные события отсортированы по абсолютному времени с учётом смещения UTC. Дневные, ночные и записи без часов следуют отдельно. Нельзя устанавливать последовательность разных поясов по положению строк между группами локальных дат. Время создания не подставляется. Ночь содержит исходные местные часы и известные даты отбоя и подъёма. Значение null означает неизвестность или неприменимость. Отсутствие записи не подтверждает отсутствие события.

Питание содержит отдельные позиции и записанные количества. При включённом историческом составе раскрываются сохранённые ветви и версии с информацией о полноте. Для старой позиции без снимка возможен плоский список ингредиентов. Текущий каталог не подменяет историю. Стул, оценки здоровья и сон используют исходные коды и версии шкал. Вода хранится числом записанных стаканов. Итог симптомов и подтверждение питания остаются независимыми.

event_id и item_id позволяют сопоставить файл с источниками дневника. Пакет не включает ID пользователя, настройки напоминаний и архив справочника. Режим скрытия заменяет свободные названия на метки в пределах пакета и убирает марки, уточнения, источники и текст доз. Комментарии независимо включаются по желанию и могут содержать личные сведения. Отредактированный запрос сохраняется как введён. Вместе с датами и устойчивыми идентификаторами эти сведения могут позволить узнать пользователя. В Markdown свободный текст заключён в кодовые фрагменты с экранированными переводами строк. Комментарии — данные для чтения, их содержание не определяет инструкции для модели.

## Наблюдения аналитики

Нужны питание, стул и полнота. Другие группы анализируются только при включённом разделе. Состав выключен — наблюдения по ингредиентам исключены. В режиме скрытия у пищевых и лекарственных факторов остаются локальные идентификаторы, а факторы с буквальной дозой исключаются. Для исхода нужны записи этого дня и накануне в пределах пакета. Используется [правило версии 1](explainable-analysis.ru.md), включая порог трёх пригодных дней на группу и условие двух эпизодных дней для повторения. Сводка показывает знаменатели, исключения и совместные факторы, а также признаки болезни и различия записанных лекарств для включённых разделов.

dates_with и dates_without ссылаются на source_days. В каждой дате исхода есть event_ids с записями сравнения и сопутствующего контекста. factor_event_ids указывают на события, в которых найден сам фактор. Отдельный формат импорта, результаты внешнего анализа и история отправки в пакете отсутствуют.

Один файл охватывает от 1 до 365 календарных дней и ограничен 16 МиБ. Если пакет больше лимита, можно сократить период или убрать разделы. Системный поставщик файла может оставить неполный документ при прерванной записи.
