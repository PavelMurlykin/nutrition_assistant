# Единый интерфейс Nutrition Assistant

Результат этапа 3, версия приложения 0.6.0. Схема Room 4 и JSON 1 не меняются.

## Общие правила

- Все текстовые роли темы используют `FontFamily.SansSerif`. Заголовки, основной текст, подписи и кнопки берут стили из `NutritionTypography`; размер следует системному масштабу шрифта.
- Сохраняются зелёная палитра и светлая/тёмная темы. Цвета текста, поверхностей, ошибок и полей берутся из `MaterialTheme`, без отдельной палитры для всплывающих окон.
- Карточки и окна используют общие скругления темы; поля — общую форму среднего размера. Поля, выборы и кнопки имеют подписанные состояния, недопустимый ввод не сохраняется.
- Для экранов используются отступы 16 dp; внутри форм — интервалы 12 dp, между действиями — 8 dp. Списки и длинные формы прокручиваются, действия переносятся на новую строку при недостатке ширины.
- Заголовки карточек могут занимать две строки. Вторичный текст использует `onSurfaceVariant`, а не отдельную полупрозрачную краску.

## Компоненты

| Компонент | Назначение |
| --- | --- |
| `AppDialog` | Общая поверхность, заголовок, прокручиваемая область, индикатор операции и действия |
| `AppDismissButton` | «Отмена» через тот же обработчик, что возврат и нажатие вне окна |
| `AppTextField` | Общие шрифт, форма, подпись, ошибка, одно-/многострочный ввод |
| `AppRadioChoice` | Подписанный выбор Бристольской шкалы с семантической ролью радиокнопки |
| `ConfirmActionDialog` | Удаление записи, скрытие справочника, подтверждение отмены черновика |
| `AppDatePicker` | Строгий ввод ДД.ММ.ГГГГ, включая проверку реальной даты и високосного года |
| `AppTimePicker` | Строгий ввод времени ЧЧ:ММ, 24-часовой формат |

Общая оболочка ограничивает ширину 640 dp и учитывает безопасные поля и клавиатуру. При обычной высоте кнопки отделены от прокручиваемого содержимого. При низком окне или крупном шрифте в низком окне вся форма может прокручиваться, чтобы действия оставались достижимыми. Это прокручиваемая панель; длинные редакторы не ограничиваются прежним узким системным AlertDialog.

Дата и время вводятся цифрами: восемь цифр даты и четыре цифры времени; точки и двоеточие добавляются автоматически. Ведущий ноль времени обязателен. Подтверждение применяется только по «Выбрать». Нативные `android.app.DatePickerDialog` и `TimePickerDialog` больше не используются.

## Состояние и действия

- Вид открытой формы и идентификатор редактируемой записи сохраняются как небольшие значения состояния; данные записи повторно читаются из дневника/справочника.
- Текст, фильтры, выбранные продукты/позиции и дозировки сохраняются при пересоздании экрана. Для состава приёма пищи/лекарства применяется отдельный Saver, включая исторические отображаемые сведения.
- Черновик не создаёт событие в базе автоматически. Вложенное создание сохраняет продукт/блюдо/лекарство отдельно; отмена родительской формы не удаляет такую запись, о чём сказано в редакторе.
- При изменённых значениях формы «Отмена», возврат и нажатие вне поверхности предлагают «Отбросить». Отмена этого подтверждения оставляет черновик открытым.
- Удаление дневника и архивирование справочника проходят через подтверждение. Составы справочника и история сохраняются в соответствии с существующей моделью данных.
- Во время сохранения окно не закрывается, повторная операция блокируется. Недопустимые значения подсвечиваются, сохранение отключается.
- Ошибка действия с дневником/каталогом показывается общим окном над формой; введённые значения не сбрасываются. Статусы файловых операций остаются на экране «Данные».

## Перечень охваченных окон

| Область | Окна |
| --- | --- |
| Дневник | Выбор вида записи, приём пищи, приём лекарства, стул, самочувствие, вода, сон |
| Справочники | Продукт, блюдо, лекарство, вложенное создание продукта из блюда и позиции из события |
| Дата и время | Переход к дате дневника, время напоминания, отбой и подъём |
| Данные | Предпросмотр импорта, сопоставления, конфликты, восстановление справочника и настроек |
| Подтверждения | Удаление события, скрытие справочника, отмена изменённой формы |
| Ошибки | Ошибка сохранения/действия с доступом к исходному черновику |

Системный выбор файлов, разрешения уведомлений и настройки Android оформляются самой системой. После завершения процесса импортный файл выбирается заново — это ограничение этапа 2 сохраняется. Документ не обещает восстановление любого черновика после завершения процесса или очистки данных.

## Проверки

- Существующие сценарии календаря, справочников и JSON продолжают работать.
- Незавершённый рецепт сохраняет название, запрос поиска и выбранный продукт после пересоздания Activity; отмена требует отдельного решения и позволяет вернуться к черновику.
- Незавершённый приём пищи сохраняет выбранную позицию после пересоздания Activity.
- Время и дата сохраняют черновик, автоматически форматируют цифры, отвергают неверный час и невисокосное 29 февраля; подтверждение сохраняет значение или выбранную дату.
- В светлой теме с обычным шрифтом и тёмной теме с шрифтом 200% поле с клавиатурой и действие сохранения остаются доступны; сохраняются снимки для визуальной проверки.
- Сохраняются проверки горизонтального экрана, календаря, крупного текста и полного восстановления JSON. Запускаются сборка, модульные/Android-тесты и lint.

При последующих этапах следует расширять эти компоненты, сохраняя общее оформление и проверки доступности. Основание для сохранения UI-состояния: [Android Developers, Save UI state in Compose](https://developer.android.com/develop/ui/compose/state-saving).

## Дополнения этапа 5

Редакторы продуктов и блюд, категория продукта, просмотр состава/источников, сравнение исторического и текущего состава, выбор недавнего приёма и разрешение неоднозначного встроенного продукта используют те же `AppDialog` и `AppTextField`. Дополнительные сведения и количества раскрываются по запросу; длинные списки компонентов ограничены по высоте и прокручиваются. Просмотр дерева выводит до 200 узлов, полный состав хранится в модели и JSON.

Переход к выбору еды доступен после загрузки выбранного дня. UI-проверки ожидают готовые счётчики и прокручивают вложенный список перед нажатием компонента; действия должны быть видимыми пользователю. Избранное и архив не меняют прошлые снимки.

## Дополнения этапа 6

Быстрый день, отдельное наблюдение, сон, Bristol с дополнительными оценками и полнота используют AppDialog/AppTextField и общий ScalePicker. Начальный выбор отсутствует, комментарии и дополнительные категории раскрываются по желанию. Зависимые поля очищаются при несовместимом ответе; дневной период убирает точный час. Фактическое время, UTC-смещение и пояс доступны в еде, лекарствах и событиях состояния. Черновики сохраняются при восстановлении Compose, подтверждение отмены остаётся общим. Формы проверяются в светлой теме 100% и тёмной 200%; длительность ввода на реальном пользователе отдельно не измерялась.
