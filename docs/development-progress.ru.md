# Прогресс доработки Nutrition Assistant

Обновлено: 17 ноября 2026 года. Основание: [план развития](development-roadmap.ru.md).

## Правила продолжения

- Реализуется один этап за запуск в текущем чате. Незавершённый этап продолжается до начала следующего.
- Готовность определяется результатами и проверками, а не наличием описания в плане.
- После проверок создаётся коммит этапа и выполняется обычный push в `origin/main`. Следующий этап разрешён только после подтверждённой отправки предыдущего.
- Для определения коммита использовать таблицу и историю Git. Если строка указывает «коммит этапа», найти его по номеру и сообщению, затем сравнить с удалённой веткой. Собственный SHA невозможно записать внутри того же коммита.
- Если коммит существует только локально, сначала завершить его отправку. Не выполнять повторную реализацию и не помечать push успешным по локальной записи.

- Запущен вручную по поручению пользователя 17 ноября 2026 года. Остальные этапы остаются в активном расписании каждые 30 минут.
- Исходная версия: `092b646` в ветке `main`; исходных изменений кода нет. Незакоммиченный план создан в этом чате и входит в первый коммит этапа.
- Создана [спецификация](product-specification.ru.md): различия продуктов и вариантов, вложенный состав, категории, обязательные поля, UUID, версии, снимки истории, время, полнота дня, шкалы, комментарии, правила миграций и backup.
- Подготовлены синтетический набор продуктов/блюд и 33 сценария S01–S33 с ожидаемыми результатами, этапами проверки и покрытием всех пунктов видения.
- Зафиксированы короткие формы, единый стиль и рабочие предположения. Правовые вопросы магазинов и пригодность модели остаются исследованиями этапов 10–11 и не блокируют backup.
- В README добавлены ссылки на план, спецификацию и журнал. Код, схема базы и доступное пользователю поведение не менялись.
- Русское и английское руководства полностью прочитаны и сверены с текущими моделями, редакторами, валидацией, темой, настройками сборки и manifest. Они остаются без изменений: новые функции не представлены как доступные.
- Проверки: относительные ссылки четырёх документов существуют; идентификаторы S01–S33 уникальны; журнал содержит 11 этапов; ошибочных символов Unicode и пробелов в конце строк нет. `git diff --check` пройден; перед коммитом также проверяется индексированная версия.
- Сборка, lint и Android-тесты не запускались: изменения только в документации. Сценарии S01–S33 являются будущими критериями приёмки, а не отчётом о прохождении тестов приложения.

## Этап 2 — результат

- Запущен вручную по поручению пользователя и завершён после продолжения в текущем чате. Этапы 3–11 остаются в расписании каждые 30 минут.
- Исходная ветка `main`, удалённый `main` перед коммитом содержит `e71a49c`; посторонних изменений в исходном состоянии не было.
- Приложение 0.5.0 / код 6, схема Room 4. Миграция 3 → 4 добавляет постоянные UUID десяти переносимым таблицам и явные сопоставления импорта; прежние записи, ссылки и снимки сохраняются. UUID остаются прежними при редактировании.
- Добавлена вкладка «Данные»: экспорт полного согласованного снимка JSON 1, импорт через системный выбор файла, строгая проверка до записи и предпросмотр. Поддерживается один локальный профиль; лимиты — 16 МиБ и 100 000 объектов и компонентов.
- Повторный импорт узнаётся по UUID и подтверждённым соответствиям. Сопоставление одноимённых справочников и сохранение локальных конфликтующих событий требуют явного выбора. Состав/архив справочника и настройки можно отдельно восстановить из файла; по умолчанию остаются локальные значения. Исторические названия, составы, дозировки и порядок позиций сохраняются независимо от текущего справочника.
- Применение — одна транзакция, проверяется актуальность предпросмотра по SHA-256. Отмена, повреждённый файл, устаревший предпросмотр и искусственная ошибка SQLite не приводят к частичной записи. Напоминания пересоздаются из выбранных настроек; дополнительные разрешения на накопитель и интернет не добавлены.
- Описан [формат JSON 1](backup-format.md), добавлен [синтетический пример](examples/nutrition-backup-v1.json), который читается в тестах тем же декодером. Обновлены README и оба руководства пользователя с одинаковыми шагами и ограничениями.
- Проверки с JDK 21: `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:connectedDebugAndroidTest` и отдельный `:app:lintDebug` завершились успешно. Пройдены 11 модульных и 29 Android-тестов на Medium_Phone / Android 17; lint сообщает `No issues found`.
- Проверены миграции 1 → 2 → 3 → 4, восстановление всех типов данных, архив предустановленной позиции, настройки, исторические снимки, порядок позиций, повторный импорт, конфликты, отмена и откат. В существующем календарном UI-тесте удаляется именно добавленная последняя запись, чтобы ранее сохранённые записи не нарушали проверку.
- Дополнительно на эмуляторе проверен реальный путь через системный файловый провайдер: экспорт JSON сохранён в Downloads, файл выбран для импорта, предпросмотр показал 0 новых объектов / 22 совпадения, после применения показано успешное завершение без дублей.
- Относительные ссылки документации и `git diff --check` проверены. Полная замена базы, синхронизация, несколько профилей и будущая аналитическая выгрузка в эту версию не входят. Незашифрованный JSON содержит сведения о здоровье; прерванная запись внешнего файла может оставить неполный документ.
- Сообщение коммита: `feat: этап 2 — добавить резервные копии JSON`.
- Следующий этап — 3, единый интерфейс, по сохранённому расписанию. Перед началом необходимо подтвердить присутствие коммита этапа 2 в `origin/main`; если push не завершился, сначала отправить его.
