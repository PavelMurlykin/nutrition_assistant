# Объяснимая аналитика — правило 1, этап 8

Реализовано в приложении 0.11.0 / code 12. Room 8, экспорт JSON 5, импорт JSON 1–5. Аналитика локальная и описательная: не рассчитывает вероятность диагноза, не подтверждает непереносимость и не назначает лечение или исключение продуктов. Комментарии остаются текстом пользователя без автоматического смыслового разбора.

## Два разных сопоставления

| Представление | Период | Условия |
| --- | --- | --- |
| Сравнение календарных дней | 30/90/365 дней до выбранной даты, выбранный день исключён | Подтверждены питание накануне и итог симптомов; неизвестность учитывается для каждого фактора |
| Контекст конкретного эпизода 6/7 | Настраиваемые окна 0–6, 6–24, 24–48 часов | Только указанные часы со смещением UTC; нижняя граница исключена, верхняя включена |
| Неопределённый календарный контекст | Еда/лекарства накануне, оценки выбранного дня и ночи | Не утверждает точный порядок относительно эпизода |

Период ограничен поддерживаемыми датами 0001–9999; у начала диапазона знаменатель сокращается, а 0001-01-01 не имеет предыдущих доступных дней.

Выбранный день не включается в сравнения предыдущих дней: позднее событие этого дня не объясняет более ранний эпизод через агрегат. Часовые окна являются исследовательскими предположениями приложения, а не универсальными медицинскими сроками. Равное время не устанавливает взаимный порядок. События после эпизода не входят в предшествия; отдельно показано число таких исключённых событий.

Для точного окна сравниваются Instant из исходных даты, HH:mm и UTC-смещения; исходная дата остаётся в календаре. Поэтому при смене пояса событие с более поздней локальной датой может быть раньше по UTC. Поиск охватывает запас календарных дат для смещений до ±18 часов, затем фильтруется абсолютным временем. Записи без времени не получают час из createdAt и не попадают в точное окно. Неопределённые часы показаны отдельно по датам последних двух дней и выбранного дня. Дневные оценки/сон также отделены. Из календарного контекста убираются события с известным равным/более поздним Instant.

## Пригодность дней и знаменатели

Для исхода D требуется symptoms_complete и явный итог: diarrhea с записанным 6/7, no_diarrhea без 6/7 либо no_stool без записей стула. Питание D−1 должно быть подтверждено. Подтверждённый пустой рацион допустим как ответ пользователя; неполный день не становится отсутствием воздействия. Несколько эпизодов в D дают один affected day; счётчик эпизодов хранится отдельно от дней.

- **Позиция еды:** присутствие блюда/продукта из сохранённой записи. Отсутствие именно позиции требует полного питания, но не означает отсутствия того же продукта внутри других блюд.
- **Компонент:** узлы исторического вложенного состава. Известное присутствие используется даже при частичном составе; отсутствие — только когда всё питание D−1 имеет полностью известный состав. Старый плоский список остаётся помеченным отдельно, его отсутствие не доказывает отсутствие компонента.
- **Рецепт и вариант:** UUID и версия узла берутся из снимка. Изменение справочника не переписывает прошлую еду. Разные версии позиции/компонента не смешиваются, неизвестная старая версия подписана явно. Путь «котлета → фарш → чеснок», источник состава и количества доступны в исходных записях.
- **Порция:** дополнительный фактор для отдельного записанного количества и единицы позиции. Порции не складываются за день; 75 г + 75 г не создают запись порции 150 г. Если нужная позиция встречалась без количества, отсутствие конкретной порции неизвестно. Известная положительная запись остаётся пригодной.
- **Лекарство:** фактические записи D−1; дополнительно нужны подтверждённые наблюдения D−1. Факт приёма и точные дозировки/количества сравниваются отдельно. Дозировка — буквальный пользовательский текст, без пересчёта эквивалентных написаний. Неизвестная доза/количество не становится другой дозой/количеством.
- **Стресс, активность, самочувствие, болезнь:** только явные дневные оценки D. Нужен известный код/версия; пропуск не становится нулём. Болезнь unknown не становится none и исключается из таких сравнений. Дневная оценка не объявляется предшествовавшей эпизоду независимо от времени её ввода. Отдельные моментные оценки участвуют в часовом контексте при наличии времени.
- **Сон:** качество отнесено к выбранной пользователем завершившейся ночи D. Новую оценку без часов можно использовать без выдуманного интервала. Старые часы без уточнённых дат ночи не создают пригодную ночь; балл/даты не угадываются. Сон не превращается в событие пробуждения с UTC-временем, взаимный порядок с эпизодом не утверждается.

Покрытие показывает длину периода, подтверждения и пригодные пары, дни/эпизоды 6/7, число позиций с неполным составом, событий без часов и непригодных оценок ночи. События с несколькими позициями не умножают счётчик событий без часов. У каждого фактора свой знаменатель; исключённые по полноте/неизвестности дни показаны явно.

## Числа и неопределённость

Выбранные до проверки на синтетических сценариях пороги правила 1: минимум **3 пригодных дня в каждой группе**; для «Повторяющегося совпадения» дополнительно минимум **2 affected days с фактором** и более высокая частота с ним. Частоты сравниваются целыми перекрёстными произведениями, без деления на ноль. Меньшие группы получают «Недостаточно данных», одиночное событие не получает повторение. Это продуктовые пороги, не доказанная статистическая мощность, значимость или медицинская валидность. Отсутствие более высокой частоты не доказывает переносимость.

Список алфавитный по группе и названию, без рейтинга риска. При совпадении наборов положительных пригодных дней (не менее двух) отмечаются совместные факторы; их независимое влияние не установлено. Показаны первые восемь названий и общее число, чтобы большие совместные группы не создавали квадратичный объём результата. Категории используются для фильтра и групповой сводки присутствия в пригодных днях; одинаковая категория не означает одинаковой переносимости.

Отдельно показаны дни с отмеченными признаками болезни, неизвестной оценкой и различиями записанных лекарств D/D−1. Явное отсутствие за день отличается от пропуска; отсутствие признаков в отдельный момент не подтверждает отсутствие за весь день. Сравнение лекарств выполняется только при подтверждённых наблюдениях обоих дней; иначе изменение неизвестно. Оно отражает записи, а не изменение назначения. Болезнь/лекарства в день исхода — сопутствующие обстоятельства, не доказанные предшествующие причины. В часовом контексте лекарство после эпизода исключено из предшествий.

## Исходные записи и профиль

Из наблюдения доступны обе группы дней, исходный итог симптомов, записи фактора, остальные записи дня/накануне и комментарии; затем можно открыть дневник нужной даты. Сохраняются названия, пути, порции и дозировки на момент записи, без подмены текущим каталогом. Пропуск исходного события не придумывается при подтверждённом no_stool.

«Что хочу отслеживать» связывает стабильную идентичность каталога со scope entry (позиция) либо ingredient (компонент продукта), источником предположения и комментарием. Профиль не имеет состояния подтверждённой непереносимости. История показывает упоминания в составе питания до выбранной даты, включая разные версии рецепта. Деактивация сохраняет заметки и идентичность. Повторный выбор существующей пары каталог/scope использует прежнюю запись; пустые поля при добавлении сохраняют прежние заметки, явное редактирование позволяет их очистить.

Room читает историю одной наблюдаемой транзакцией с отношениями; расчёт отчёта и контекста выполняется вне UI-потока. Производные отчёты не сохраняются как медицинские события. Период, окно и фильтры относятся к состоянию экрана; JSON переносит исходный дневник и профиль, из которых отчёт строится заново.

Для [выгрузки выбранного периода](analysis-export.ru.md) расчёт ограничен данными пакета. Последняя дата может быть днём исхода, если накануне есть пригодные записи в этом же пакете.

## Перенос и проверка

Миграция 7→8 добавляет пустую tracking_targets, сохраняя старые записи. JSON 5 добавляет профиль со ссылками на users/catalog; словарь шкал версии 1 сохраняется. JSON 4 проверяется по прежнему точному набору таблиц; JSON 1–3 проходят существующие адаптеры. Старые файлы не создают выдуманных предположений. При конфликте профиля с тем же каталогом/scope сохраняется локальный вариант после явного выбора, UUID-сопоставление предотвращает дубли.

Синтетические проверки охватывают повторение/отсутствие повышения, малые группы, пропуски, неизвестный состав, версии рецепта, совместные факторы, порции/дозы и их неизвестность, болезнь unknown, сон, лекарство после эпизода, границы часов/суток/поясов, будущие события, JSON и миграции. UI-проверки проверяют знаменатели, путь состава, источник/комментарии, переход к дневнику, восстановление предположения и крупный шрифт. Фактические итоги и ограничения фиксируются в [журнале](development-progress.ru.md).

Выбор нескольких групп показателей соответствует тому, что при поиске причин врачи рассматривают питание, лекарства, симптомы и медицинскую историю; дневник не заменяет такую оценку. Источники, проверенные 18 ноября 2026 года: [NIDDK, диагностика диареи](https://www.niddk.nih.gov/health-information/digestive-diseases/diarrhea/diagnosis), [NIDDK, симптомы и причины](https://www.niddk.nih.gov/health-information/digestive-diseases/diarrhea/symptoms-causes). Порогов 3/2 и часовых окон эти источники не обосновывают: это явно обозначенные предположения приложения.
